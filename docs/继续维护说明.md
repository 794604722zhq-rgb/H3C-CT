# 继续维护说明

本说明用于在更换电脑或更换 ChatGPT/Codex 账号后继续维护选型助手。GitHub 仓库是网页版本的长期保存位置，与 ChatGPT 账号无关。

## 一、快速恢复

1. 登录拥有 `794604722zhq-rgb/H3C-CT` 仓库权限的 GitHub 账号。
2. 在新电脑安装 Git，并克隆仓库：

   ```text
   git clone https://github.com/794604722zhq-rgb/H3C-CT.git
   ```

3. 打开仓库根目录的 `index.html`，或直接访问 <https://794604722zhq-rgb.github.io/H3C-CT/>。
4. 若由新的 ChatGPT/Codex 账号继续维护，可把仓库地址发给它，并要求先阅读 `README.md` 和本文件，再开始修改。

可直接使用下面这段接续说明：

> 请继续维护 GitHub 仓库 https://github.com/794604722zhq-rgb/H3C-CT 。先阅读 README.md 和 docs/继续维护说明.md，保留现有两个助手、数据结构、匹配规则、招标引导和 GitHub Pages 发布方式；修改后先测试，再通过分支和 PR 合并到 main。

## 二、目录结构

- `index.html`：两个助手的统一入口。
- `h3c-selector/`：新华三正式交换机与无线产品选型助手。
- `h3c-selector/data/products.js`：正式产品网页数据库。
- `h3c-selector/guides/`：各产品系列的招标引导页面与参数数据。
- `xiaobei-selector/`：小贝优选产品选型助手。
- `xiaobei-selector/data/products.js`：小贝优选网页数据库。
- `.github/workflows/pages.yml`：GitHub Pages 自动发布配置。

网页数据已内置，使用工具时不依赖本地 Excel。

## 三、现行识别与推荐规则

### 通用单位

- 交换容量：`T` 与 `Tbps` 等价，`G` 与 `Gbps` 等价。
- 包转发率：`M` 与 `Mpps` 等价。
- 端口速率：`1G` 与 `1GE` 等价。

### 端口叫法

- `10/100/1000Mbps 自适应电口`按千兆电口识别。
- `100/1000/2500Mbps 自适应电口`按 2.5G 电口识别。
- `SFP 口`、`SFP 千兆光口`按千兆光口识别。
- `SFP+ 口`、`SFP+ 万兆光口`按万兆光口识别。
- 混合速率描述按可支持的最高速率理解。例如“10G/2.5G/1G 接口数不少于 20，25G/10G 接口数不少于 4”按“10G 不少于 20、25G 不少于 4”处理。
- 结果中应分别显示“需求数量”和“产品可用数量”，避免把多个口型合并成难以理解的一句话。

### 框式交换机

- 主要硬条件：交换容量、包转发率、主控板数量、交换网板数量、业务板数量。
- 框式交换机的端口配置不作为主要筛选条件。
- 主控板、交换网板、业务板、风扇、电源和硬件架构信息保留在产品数据中。

### 扩展槽与选配组件

- `1×业务插槽`、`1个 slot`、`1个扩展槽位`按相同含义识别。
- 对非框式且带扩展槽的产品，结果页显示官网产品选配页面列出的可选组件。
- 选配组件只以官网选配页面为准，不扩展查询硬件手册兼容表。

### 排序规则

- 先满足硬性条件，再比较与需求参数的接近程度；满足条件且余量更小的型号优先。
- RS 系列属于弱电款型，在正式新华三助手中降低到最低推荐优先级。
- 小贝优选助手中，其他条件和接近程度完全相同时，价格更低的产品优先。

## 四、招标引导

- 搜索结果命中已配置系列时，显示招标引导入口。
- 招标引导页支持多选参数、实时预览和复制最终文本，不提供下载功能。
- 新增产品招标引导时，沿用 `h3c-selector/guides/` 下现有系列的目录结构和交互方式。

## 五、数据更新原则

- 新华三正式产品参数以 H3C 中文官网为准。
- 官网有最大值和最小值时分别记录；只有一个值时写入最小值字段。
- 公用的系列参数可复制到同系列适用型号，但需要确保官网口径一致。
- 小贝优选数据可保留渠道价格用于同条件下排序，但价格和供货状态需按最新渠道资料更新。
- 修改数据库后，同时检查页面显示、筛选结果、排序结果和招标引导链接。

## 六、版本发布

1. 从最新 `main` 创建 `codex/` 开头的分支。
2. 仅提交本次确认修改的文件。
3. 完成本地页面与关键匹配场景测试。
4. 推送分支并创建 PR，检查后合并到 `main`。
5. GitHub Actions 会自动发布 Pages；发布完成后检查在线首页和两个助手。

## 七、公开仓库边界

当前仓库是公开仓库。源 Excel、原始价格表、Windows 启动脚本以及其他可能包含内部信息的文件通过 `.gitignore` 排除，不应直接提交。若后续需要完整保存这些原始资料，应使用单独的私有仓库或私有云盘，并在公开前检查内容。
